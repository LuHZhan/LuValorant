在Unreal Engine 5中，继承自`AActor`的类构造函数在编译后被调用，主要与引擎的**类注册流程**和**类默认对象（CDO，Class Default Object）**的生成机制有关。以下是详细解释：

---

### 1. **类注册与反射系统**
Unreal Engine使用反射系统（Reflection System）动态管理类的元数据。通过`UCLASS()`宏标记的类会在引擎启动或模块加载时进行注册。注册过程中，引擎会：
   - 为每个`UClass`生成元数据（如属性、函数、接口等）。
   - 创建该类的**类默认对象（CDO）**，即一个用于存储类默认属性值的全局单例。

   **每个类的构造函数会被调用一次以生成CDO**，这是UE对象系统的核心机制。

---

### 2. **为什么构造函数会被调用？**
- **CDO生成的必要性**  
  当引擎加载包含Actor派生类的模块（如游戏模块、插件）时，会为每个`UClass`创建其CDO。CDO的作用包括：
  - 提供属性的默认值（在编辑器中显示的默认值）。
  - 作为蓝图和C++类的模板，生成实例时从此复制初始值。
  
  生成CDO时，必须调用该类的构造函数以正确初始化默认值。

- **热重载（Hot Reload）的影响**  
  在编辑器中触发编译（如修改代码后的热重载）时，模块会被重新加载。此时所有类的CDO会重新生成，导致构造函数再次被调用。

---

### 3. **何时触发构造函数调用？**
- **编辑器启动时**：加载所有已注册的模块和类。
- **模块动态加载时**：如游戏运行时加载插件或子模块。
- **热重载后**：重新编译代码并刷新模块。

---

### 4. **用户观察到的现象**
如果在构造函数中添加了日志（如`UE_LOG`），会发现：
- 每次编译后（尤其是热重载），日志会输出一次，表明构造函数被调用。
- 每个`AActor`派生类的构造函数都会被调用，因为每个类都需要生成自己的CDO。

---

### 5. **如何避免不必要的副作用？**
构造函数中应**仅初始化默认属性**，避免执行游戏逻辑或资源加载。如果需要在Actor进入场景时执行逻辑，应使用`BeginPlay()`：

```cpp
AMyActor::AMyActor()
{
    // 仅初始化默认值（如组件、变量）
    PrimaryActorTick.bCanEverTick = true;
    MyComponent = CreateDefaultSubobject<USceneComponent>(TEXT("Root"));
}

void AMyActor::BeginPlay()
{
    Super::BeginPlay();
    // 游戏逻辑或资源加载（安全位置）
}
```

---

### 6. **总结**
- **根本原因**：UE的反射系统需要为每个`UClass`生成CDO，而CDO通过调用类构造函数创建。
- **触发时机**：模块加载、热重载、编辑器启动时。
- **正常行为**：这是引擎设计的预期行为，无需修复，但需遵循最佳实践（如将逻辑放在`BeginPlay`中）。

如果希望进一步了解UE的对象系统，可查阅官方文档中的**Unreal Object Handling**和**Class Default Object**相关内容。
