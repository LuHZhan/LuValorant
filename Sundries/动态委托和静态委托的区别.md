# UE5中静态委托和动态委托的区别

在虚幻引擎5中，委托系统分为静态委托和动态委托两种主要类型。它们在实现、性能和使用场景上有明显区别。

## 基本区别

### 静态委托
- 在C++代码中定义和使用
- 编译时绑定
- 更高的性能
- 不支持蓝图交互
- 使用模板实现

### 动态委托
- 支持C++和蓝图交互
- 运行时绑定
- 性能相对较低
- 支持序列化和网络复制
- 使用反射系统实现

## 定义方式

### 静态委托
```cpp
// 单播静态委托
DECLARE_DELEGATE(FMyDelegate);
DECLARE_DELEGATE_OneParam(FMyDelegateOneParam, int32);

// 多播静态委托
DECLARE_MULTICAST_DELEGATE(FMyMulticastDelegate);
DECLARE_MULTICAST_DELEGATE_TwoParams(FMyMulticastDelegateTwoParams, int32, FString);
```

### 动态委托
```cpp
// 单播动态委托
DECLARE_DYNAMIC_DELEGATE(FMyDynamicDelegate);
DECLARE_DYNAMIC_DELEGATE_OneParam(FMyDynamicDelegateOneParam, int32, MyParam);

// 多播动态委托
DECLARE_DYNAMIC_MULTICAST_DELEGATE(FMyDynamicMulticastDelegate);
DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(FMyDynamicMulticastDelegateTwoParams, int32, MyParam1, FString, MyParam2);
```

## 执行函数的区别

### 静态委托执行
静态委托的执行是通过直接调用函数指针或函数对象实现的：

1. **直接调用**：静态委托存储的是函数指针或函数对象，执行时直接调用这些函数。
2. **编译时绑定**：绑定关系在编译时确定，没有运行时查找开销。
3. **类型安全**：参数类型在编译时检查，类型不匹配会导致编译错误。
4. **执行代码**：在`DelegateSignatureImpl.inl`中，静态委托的执行通过`Execute`方法直接调用存储的函数指针：
   ```cpp
   FORCEINLINE RetValType Execute(ParamTypes... Params) const
   {
       FReadAccessScope ReadScope = GetReadAccessScope();
       const DelegateInstanceInterfaceType* LocalDelegateInstance = GetDelegateInstanceProtected();
       checkSlow(LocalDelegateInstance != nullptr);
       return LocalDelegateInstance->Execute(Forward<ParamTypes>(Params)...);
   }
   ```

### 动态委托执行
动态委托的执行涉及到反射系统和UFunction：

1. **间接调用**：动态委托存储的是UFunction名称和对象引用，执行时需要通过反射系统查找函数。
2. **运行时绑定**：绑定关系在运行时确定，有额外的查找开销。
3. **类型转换**：参数需要在运行时进行类型转换，可能有额外的性能开销。
4. **执行代码**：动态委托通过`ProcessEvent`系统调用UFunction：
   ```cpp
   // 简化的执行流程
   void UObject::ProcessEvent(UFunction* Function, void* Parms)
   {
       // 查找函数
       // 参数打包
       // 调用本地或远程函数
       // 参数解包
   }
   ```

## 性能对比

1. **静态委托**：几乎与直接函数调用一样快，只有极小的额外开销。
2. **动态委托**：由于涉及反射系统和可能的序列化/反序列化，性能开销明显更大。

## 使用场景

- **静态委托**：适用于性能敏感的C++代码，如游戏逻辑核心、物理系统等。
- **动态委托**：适用于需要蓝图交互、网络复制或热重载的场景，如UI事件、游戏玩法逻辑等。

在实际开发中，应根据具体需求选择合适的委托类型，平衡性能和灵活性。
