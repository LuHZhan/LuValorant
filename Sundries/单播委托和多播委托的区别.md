在 Unreal Engine 5（UE5）中，**委托（Delegate）** 是实现事件驱动编程的核心工具，而 **单播委托（Single-cast Delegate）** 和 **多播委托（Multi-cast Delegate）** 是两种主要的委托类型。它们的核心区别在于 **绑定的函数数量** 和 **触发机制**。以下是详细对比：

---

### **1. 核心区别**
| **特性**         | **单播委托** (Single-cast)                 | **多播委托** (Multi-cast)                        |
| ---------------- | ------------------------------------------ | ------------------------------------------------ |
| **绑定函数数量** | 只能绑定 **一个函数**                      | 可以绑定 **多个函数**                            |
| **返回值**       | 支持有返回值的函数（如 `int`, `bool`）     | 通常用于无返回值的函数（返回值会被忽略）         |
| **触发方式**     | 直接调用（`Execute()` 或 `Broadcast()`）   | 必须用 `Broadcast()` 触发                        |
| **适用场景**     | 需要精确控制单一回调逻辑（如任务完成通知） | 需要通知多个监听者（如玩家死亡事件触发多个系统） |

---

### **2. 声明方式（C++）**
#### **单播委托**
- **无参数无返回值**：
  ```cpp
  DECLARE_DELEGATE(FMyDelegate);
  ```
- **带参数和返回值**：
  ```cpp
  DECLARE_DELEGATE_RetVal_OneParam(int32, FMyDelegateWithParam, FString);
  ```

#### **多播委托**
- **无参数**：
  ```cpp
  DECLARE_MULTICAST_DELEGATE(FMyMultiDelegate);
  ```
- **带参数**：
  ```cpp
  DECLARE_MULTICAST_DELEGATE_OneParam(FMyMultiDelegateWithParam, FString);
  ```

---

### **3. 绑定与解绑**
#### **单播委托**
- **绑定函数**：
  ```cpp
  // 绑定 UFUNCTION 成员函数
  MyDelegate.BindUObject(this, &AMyActor::MyFunction);
  // 绑定全局函数
  MyDelegate.BindStatic(&MyGlobalFunction);
  ```
- **解绑**：
  ```cpp
  MyDelegate.Unbind(); // 解绑当前绑定的函数
  ```
- **触发**：
  ```cpp
  if (MyDelegate.IsBound()) {
      MyDelegate.Execute(); // 必须检查是否已绑定
  }
  ```

#### **多播委托**
- **绑定函数**：
  ```cpp
  // 添加绑定（允许多次调用）
  MyMultiDelegate.AddUObject(this, &AMyActor::MyFunction);
  MyMultiDelegate.AddStatic(&MyGlobalFunction);
  ```
- **解绑**：
  ```cpp
  MyMultiDelegate.RemoveAll(this); // 解绑特定对象的所有函数
  ```
- **触发**：
  ```cpp
  MyMultiDelegate.Broadcast(); // 无需检查是否已绑定
  ```

---

### **4. 返回值处理**
- **单播委托**  
  可以获取返回值：
  ```cpp
  if (MyDelegate.IsBound()) {
      int32 Result = MyDelegate.Execute("Input");
  }
  ```
- **多播委托**  
  所有绑定的函数会被触发，但返回值无法被收集（通常用于无返回值的通知）。

---

### **5. 在蓝图中的使用**
| **类型**     | **蓝图支持**                                                 |
| ------------ | ------------------------------------------------------------ |
| **单播委托** | 通常用于 C++ 逻辑，蓝图需通过动态委托（`DECLARE_DYNAMIC_DELEGATE`）暴露接口。 |
| **多播委托** | 通过 **事件分发器（Event Dispatcher）** 在蓝图中直接使用，支持多节点绑定。 |

#### **蓝图中的多播委托（事件分发器）**
1. **创建事件分发器**：在蓝图中定义事件分发器并添加参数。
2. **绑定事件**：其他蓝图可以绑定到该分发器。
3. **广播触发**：调用 `Call` 节点触发所有绑定的函数。

---

### **6. 使用场景示例**
#### **单播委托**
- **任务系统**：任务完成后触发唯一回调（如保存游戏）。
- **UI 交互**：按钮点击后执行特定逻辑（仅一个响应）。

#### **多播委托**
- **全局事件**：玩家死亡时通知 UI、成就系统、音效系统。
- **动态交互**：多个对象监听一个触发器的事件（如开门触发灯光、音效、动画）。

---

### **7. 注意事项**
1. **对象生命周期**  
   如果绑定的对象被销毁，需手动解绑委托（或使用 `WeakPtr` 防止野指针）。
2. **性能**  
   多播委托的 `Broadcast()` 会遍历所有绑定函数，高频触发时需注意性能。
3. **动态委托**  
   若需在蓝图中使用，需声明为动态委托（`DECLARE_DYNAMIC_DELEGATE`），但会略微增加开销。

---

### **总结**
- **单播委托**：精准控制单一回调，适用于需要明确结果的场景。
- **多播委托**：一对多通知，适用于需要多个系统协同响应的场景。

根据需求选择委托类型，避免滥用多播委托导致逻辑混乱！
