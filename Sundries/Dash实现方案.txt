- Modifiers: Add a modifier targeting SkillCharges, Scalable Float Magnitude = -1.0, Modifier Op = Additive.

- 确保这个GE的设置为Replicates，并且应用到Owner.

3. 创建GE_AddCharge：

- Duration Policy: Instant

- Modifiers: Add a modifier targeting SkillCharges, Scalable Float Magnitude = +1.0, Modifier Op = Additive.

4. 创建GE_ChargeCooldown：

- Duration Policy: Has Duration, 5 seconds.

- 无Modifiers.

- Expiration Effects: 添加GE_AddCharge.

- 可能需要设置Application为Apply to Self.

5. 创建GA：

- 在Ability的类设置中，设置Ability Tags等。

- Cost Gameplay Effect Class设置为GE_ConsumeCharge.

- 不需要设置Cooldown GE，因为冷却由GE_ChargeCooldown处理。

- 在ActivateAbility函数中，应用GE_ChargeCooldown：

UAbilitySystemComponent* ASC = GetAbilitySystemComponentFromActorInfo();

if (ASC)

{

FGameplayEffectContextHandle ContextHandle = ASC->MakeEffectContext();

FGameplayEffectSpecHandle SpecHandle = ASC->MakeOutgoingSpec(GE_ChargeCooldown, 1, ContextHandle);

if (SpecHandle.IsValid())

{

ASC->ApplyGameplayEffectSpecToSelf(*SpecHandle.Data.Get());

}

}

- 然后执行技能的其他逻辑，如播放蒙太奇，等待事件等。

6. 在GA的CanActivateAbility函数中，检查SkillCharges是否>=1：

bool UMyGameplayAbility::CanActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayTagContainer* SourceTags, const FGameplayTagContainer* TargetTags, FGameplayTagContainer* OptionalRelevantTags) const

{

if (!Super::CanActivateAbility(Handle, ActorInfo, SourceTags, TargetTags, OptionalRelevantTags))

{

return false;

}

UAbilitySystemComponent* ASC = ActorInfo->AbilitySystemComponent.Get();

if (!ASC)

{

return false;

}

const UMyAttributeSet* AttributeSet = ASC->GetSet<UMyAttributeSet>();

if (!AttributeSet)

{

return false;

}

return AttributeSet->GetSkillCharges() >= 1.0f;

此外，需要确保在CommitAbility时，Cost GE（GE_ConsumeCharge）能够成功应用。如果由于某种原因SkillCharges在Commit时已经不足，Commit会失败，从而阻止技能激活。

这样，整个逻辑应该可以工作。需要注意的是，应用GE_ChargeCooldown可能会被网络同步或预测影响，所以需要测试不同情况下的表现，确保客户端和服务器的同步正确。

可能还需要处理GE_AddCharge的Clamping，确保SkillCharges不会超过MaxSkillCharges，这已经在AttributeSet的PreAttributeChange中处理了。

总结：通过Cost GE扣除次数，应用一个带有Expiration Effect的GE来在5秒后恢复次数，这样每次使用都会独立处理CD，并且次数恢复正确。

在UE5的GAS框架中，实现一个可使用三次、每次使用后进入独立CD的技能，可以通过以下步骤实现：

1. 创建属性集（AttributeSet）
定义技能次数属性并设置数值钳制：

cpp
复制
// MyAttributeSet.h
#include "AttributeSet.h"
#include "MyAttributeSet.generated.h"

UCLASS()
class UMyAttributeSet : public UAttributeSet
{
    GENERATED_BODY()

public:
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Attributes")
    FGameplayAttributeData SkillCharges;
    ATTRIBUTE_ACCESSORS(UMyAttributeSet, SkillCharges)

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Attributes")
    FGameplayAttributeData MaxSkillCharges;
    ATTRIBUTE_ACCESSORS(UMyAttributeSet, MaxSkillCharges)

    virtual void PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue) override;
};

// MyAttributeSet.cpp
void UMyAttributeSet::PreAttributeChange(const FGameplayAttribute& Attribute, float& NewValue)
{
    Super::PreAttributeChange(Attribute, NewValue);

    if (Attribute == GetSkillChargesAttribute())
    {
        NewValue = FMath::Clamp(NewValue, 0.0f, GetMaxSkillCharges());
    }
}
2. 创建GameplayEffects
创建三个GameplayEffect（GE）：

GE_ConsumeCharge（消耗次数）
类型: Instant

效果: SkillCharges -1

GE_AddCharge（恢复次数）
类型: Instant

效果: SkillCharges +1

GE_ChargeCooldown（充能冷却）
类型: Duration（5秒）

过期效果: 添加GE_AddCharge

3. 实现GameplayAbility逻辑
配置技能并处理充能逻辑：

cpp
复制
// MyGameplayAbility.h
UCLASS()
class UMyGameplayAbility : public UGameplayAbility
{
    GENERATED_BODY()

public:
    virtual bool CanActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayTagContainer* SourceTags, const FGameplayTagContainer* TargetTags, FGameplayTagContainer* OptionalRelevantTags) const override;
    
protected:
    UPROPERTY(EditDefaultsOnly, Category = "Effects")
    TSubclassOf<UGameplayEffect> CooldownEffectClass;

    virtual void ActivateAbility(const FGameplayAbilitySpecHandle Handle, const FGameplayAbilityActorInfo* ActorInfo, const FGameplayAbilityActivationInfo ActivationInfo, const FGameplayEventData* TriggerEventData) override;
};

// MyGameplayAbility.cpp
bool UMyGameplayAbility::CanActivateAbility(...) 
{
    // 基础检查
    if (!Super::CanActivateAbility(...)) return false;
    
    // 获取属性组件
    UAbilitySystemComponent* ASC = ActorInfo->AbilitySystemComponent.Get();
    const UMyAttributeSet* Attributes = ASC->GetSet<UMyAttributeSet>();
    
    return Attributes && Attributes->GetSkillCharges() >= 1.0f;
}

void UMyGameplayAbility::ActivateAbility(...)
{
    // 应用冷却GE
    if (CooldownEffectClass)
    {
        FGameplayEffectSpecHandle SpecHandle = 
            GetAbilitySystemComponentFromActorInfo()->MakeOutgoingSpec(
                CooldownEffectClass, 1, GetCurrentActorInfo()->AbilitySystemComponent->MakeEffectContext());
        
        if (SpecHandle.IsValid())
        {
            ApplyGameplayEffectSpecToOwner(Handle, ActorInfo, ActivationInfo, SpecHandle);
        }
    }
    
    // 执行技能逻辑（动画、粒子等）
    CommitAbility(Handle, ActorInfo, ActivationInfo);
    
    // 结束技能（非持续型技能）
    EndAbility(Handle, ActorInfo, ActivationInfo, true, false);
}
4. 配置技能蓝图
Cost GE: 设置为GE_ConsumeCharge

CooldownEffectClass: 设置为GE_ChargeCooldown

触发逻辑: 通过输入绑定触发能力

5. 实现效果
技能使用: 每次消耗1次充能

独立CD: 每次使用后生成5秒独立计时器

充能恢复: 每个计时器结束恢复1次充能

上限控制: 充能数不超过3次

注意事项
网络同步: 确保所有GE设置为Replicates

预测支持: 对关键GE启用PredictionType

UI更新: 监听SkillCharges属性变化更新UI

冷却提示: 可通过剩余Duration显示单个充能恢复进度

此方案通过GAS的Attribute-Event机制实现了多充能技能的独立冷却管理，每个充能状态独立计算，确保技能使用逻辑清晰可靠。
